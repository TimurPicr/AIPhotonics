# Выборка из 55 000 целевых изображений

Согласованный объём относится к **отдельным целевым изображениям**, а не к четвёркам:

| Категория | PNG | Четвёрок |
|---|---:|---:|
| Синтетические, с известной общей маской | 40 000 | 10 000 |
| Независимые фотографии COCO train2017 | 5 000 | 1 250 |
| Кадры Vimeo90K Septuplet, официальный train list | 10 000 | 2 500 |
| Всего | 55 000 | 13 750 |

Это train. Существующие val/test/OOD не изменяются. Новые оценки на фотографиях и
видео требуют отдельных исходников: фотографии и исходные видео/сцены разделяют
до формирования четвёрок. Пилот является частью подготовки train, а не validation.

## Сборка

Используется окружение проекта с зависимостями из `requirements-lock.txt`.
Сборщик не требует дополнительных сторонних библиотек. Нужен доступ в интернет.

```bash
python -m src.build_dataset --root data/train55k_pilot --synthetic-quartets 100 --random-quartets 100 --similar-quartets 100 --batch-size 64
python -m src.build_dataset --root data/train55k --batch-size 64
python -m src.build_dataset --root data/train55k --verify-only
```

Можно отдельно выполнять `--category synthetic`, `--category random` и
`--category similar`. Каждый пример завершается атомарной записью `sample.json`.
Повторный запуск с теми же параметрами проверяет хеши и пропускает готовые примеры;
повреждённые примеры восстанавливаются. Параметры корневого каталога фиксируются
в `build_config.json`: изменённая конфигурация требует другого `--root`.
Две сборки в один корневой каталог одновременно не запускать.

## Генерация синтетики

По 2 500 четвёрок каждого семейства:

1. `smooth`: случайная сетка 4/8/16/32 пикселя, bicubic до 128×128, случайная сила фазы.
2. `analytic`: линейные наклоны, квадратичные фазы и синусоидальные решётки.
3. `mixed`: аналитическая фаза, гладкая случайная компонента и мелкий случайный шум.
4. `optimized`: 100 шагов Adam под процедурные геометрические, символьные,
   полутоновые и смешанные рисунки. После оптимизации целями становятся именно
   реконструкции найденной маски. MSE к первоначальным рисункам записывается отдельно.

Фазы заворачиваются по модулю 2π. Затем применяется общий путь проекта:
`export_phase_png → load_phase_png → reconstruct_four → normalize_recons → write_png`.
Четыре цели формируются из одной уже квантованной маски. Проверка заново читает
маску и цели, распространяет поле и сравнивает реконструкции после PNG-квантования.
SSIM близок к 1 **для известной генерирующей маски**; это не оценка обученной сети.
Фазовые PNG — дополнительные служебные артефакты, они не входят в 55 000 целей.
Обучение на фазовых метках автоматически не включается.

Физика зафиксирована снимком `config.py`: amplitude `abs(U)`, нормировка по
максимуму каждой плоскости, λ=532 нм, шаг SLM=10 мкм, четыре заданных расстояния.
Нативные выходные шаги пикселей записываются в manifest. Пространственные
преобразования готовых синтетических целей после распространения не применяются.

## Внешние источники

COCO: [официальные загрузки](https://cocodataset.org/#download), официальный
S3 bucket `images.cocodataset.org`. Из метаданных captions_train2017 выбираются
5 000 разных фотографий с seed 42. Загружаются только выбранные JPEG. В каждом
source record сохраняются ID, URL, SHA256 исходного JPEG, авторские metadata и
лицензия изображения из официальных аннотаций.
Повреждённые и постоянные исходники заменяются из трёх резервов, не пересекающихся
с основной выборкой и резервами других позиций; ID и причина отбраковки сохраняются.
[Условия использования COCO](https://cocodataset.org/#termsofuse).

Vimeo90K: [проект авторов](https://github.com/anchen1011/toflow).
Исходный сервер при подготовке возвращал HTTP 403. Сборщик поддерживает
публичное зеркало тех же оригинальных PNG на
[Kaggle, версия 2](https://www.kaggle.com/datasets/maiimaii/vimeo-septuplet/versions/2).
Выборка ограничивается `sep_trainlist.txt`; каждая последовательность должна
содержать все семь `im1.png`…`im7.png`. По одной четвёрке из 2 500 разных
последовательностей: чередуются кадры `[1,2,3,4]` и `[1,3,5,7]`.
Последовательности с постоянными/недекодируемыми кадрами заменяются целиком из
трёх непересекающихся резервов. Резервы рассчитаны относительно 2 500 позиций,
поэтому пилот сохраняет те же source IDs, что и начало полной выборки.
Путь в архиве, ID последовательности, номера кадров и SHA256 исходного PNG
сохраняются. Лицензия кода TOFlow не объявляется лицензией видеокадров.

Обработка фотографий: EXIF orientation → Pillow `L` → центральный квадратный
crop → LANCZOS до 128×128 → PNG uint8. Для видео применяется один crop ко всем
четырём кадрам. Нормировка фотографии по её максимуму и подбор яркости по цели
не выполняются. Постоянные изображения отбраковываются с записью причины.
У видео попарный SSIM целей хранится отдельно от SSIM оптического восстановления.

Архивы читаются по HTTP Range, без загрузки полного Vimeo-архива на ~82 ГБ.
Проверяются byte ranges, неизменность ETag, размеры и CRC ZIP members. Индексы и
официальные metadata находятся в `data/external/train55k/`.
У HTTP-ответов сверяется Content-Length; неполный ответ повторяется до декодирования.

## Результат и загрузка

```text
data/train55k/
  build_config.json
  build_status.json
  coco_selection.json
  vimeo_selection.json
  preview.png
  verification.json
  train/
    manifest.json
    manifest_synthetic.json
    manifest_random.json
    manifest_similar.json
    synthetic/synthetic_000000/{1.png,2.png,3.png,4.png,phase.png,sample.json}
    random/random_000000/{1.png,2.png,3.png,4.png,sample.json}
    similar/similar_000000/{1.png,2.png,3.png,4.png,sample.json}
```

Проверка сверяет фактическое число PNG, категории, размер/режим, хеши,
порядок плоскостей, уникальность COCO ID и Vimeo sequence ID, а также каждую
синтетическую четвёрку с её маской. `build_status.json.complete` должен быть `true`.
Только законченная выборка может пройти `--verify-only`.
Manifest содержит снимок физики, версии библиотек, Git revision и SHA256 исходников
генератора. Категории доступны как через общий, так и через три отдельных manifest.

Ленивая загрузка по одному примеру, без размещения всего набора в RAM:

```python
import torch
from src.data import ManifestDataset

dataset = ManifestDataset("data/train55k/train/manifest.json")
loader = torch.utils.data.DataLoader(
    dataset, batch_size=8, shuffle=True,
    generator=torch.Generator().manual_seed(42),
)
targets = next(iter(loader))  # float32 [8, 4, 128, 128]
```

Обычное перемешивание даёт доли 72,7% / 9,1% / 18,2%. Существующий CLI
`src.train` продолжает использовать прежний процедурный поток; подключение
фиксированного manifest к запуску обучения — отдельный шаг. Сборка не изменяет веса.

## Проверенный результат, 2026-11-07

Полная выборка собрана: 55 000 целевых PNG, 13 750 четвёрок и дополнительно
10 000 служебных фазовых PNG. Каталог занимает 909 780 291 байт.
Все цели имеют режим L и размер 128×128; хеши и порядок плоскостей проверены.
Повторное восстановление из каждой известной маски после PNG-квантования дало
минимальный SSIM 1.0. Проверены отсутствие пересечений с существующими val/test/OOD
и загрузка батча `[8,4,128,128]` через `ManifestDataset`.

Для видеочетвёрок медиана среднего попарного SSIM целей — 0.7114, диапазон
0.0993–0.9982. Поднабор определён кадрами одного клипа, жёсткий порог SSIM между
целями не вводился: в нём есть как слабое, так и сильное движение.

Тесты проекта: 56 passed, 1 skipped (Metal недоступен).
Итоги и параметры — в [outputs/dataset55k_report.json](outputs/dataset55k_report.json),
полный аудит — в `data/train55k/verification.json`.
