# Генерация фазового ДОЭ по четырём изображениям

Решение совместно обрабатывает **4 изображения 128×128** и формирует один
фазовый дифракционный оптический элемент (ДОЭ). Результат — **PNG 128×128,
8 бит, Grayscale**: один канал, режим Pillow `L`, тип цвета PNG `0`.

В репозитории находятся исходный код нейросети, обученные веса
[`weights/h100.pt`](weights/h100.pt), `Dockerfile`, `requirements.txt`
и восемь демонстрационных комплектов. Для запуска нужен только работающий
Docker. Python, библиотеки и веса устанавливать или скачивать вручную не нужно.
Интернет необходим при первой сборке; готовый контейнер работает без сети
и без GPU. Поддерживаются Linux-контейнеры `amd64` и `arm64`.

## Сборка и быстрая проверка

Команды выполняются из корня репозитория, в Bash/Zsh (Linux, macOS или WSL).

```bash
git clone https://github.com/TimurPicr/AIPhotonics.git
cd AIPhotonics
docker build -t photonics-doe .
mkdir -p output
docker run --rm --network none \
  -v "$PWD/output:/output" \
  photonics-doe --input-dir /app/examples --output-dir /output
```

В `output/` появятся **8 файлов**: `examples_0000.png` … `examples_0007.png`.
Примеры содержат геометрические объекты, символы, полутоновые и смешанные
изображения. Они служат для проверки запуска и не заменяют тесты организаторов.

Справка по параметрам: `docker run --rm photonics-doe --help`.

## Один комплект

Положите четыре изображения в папку `input/set_01/`:

```text
input/
└── set_01/
    ├── 1.png
    ├── 2.png
    ├── 3.png
    └── 4.png
```

```bash
mkdir -p output
docker run --rm --network none \
  -v "$PWD/input:/input:ro" \
  -v "$PWD/output:/output" \
  photonics-doe --input-dir /input/set_01 --output /output/phase.png
```

Результат: `output/phase.png`.

## Пять и более комплектов

Для каждого комплекта создайте отдельную подпапку с четырьмя изображениями:

```text
input/
├── set_01/  # 1.png, 2.png, 3.png, 4.png
├── set_02/  # 1.png, 2.png, 3.png, 4.png
├── set_03/  # 1.png, 2.png, 3.png, 4.png
├── set_04/  # 1.png, 2.png, 3.png, 4.png
└── set_05/  # 1.png, 2.png, 3.png, 4.png
```

```bash
mkdir -p output
docker run --rm --network none \
  -v "$PWD/input:/input:ro" \
  -v "$PWD/output:/output" \
  photonics-doe --input-dir /input --output-dir /output
```

Будут записаны `output/set_01.png` … `output/set_05.png` — по одному ДОЭ
на комплект. Число комплектов не ограничено пятью; каждый обрабатывается
отдельно одной и той же обученной моделью. Входная папка может содержать
либо один комплект, либо непосредственно подпапки комплектов.

## Порядок и формат входов

Изображения внутри комплекта сортируются по имени. Рекомендуемые имена —
`1.png`, `2.png`, `3.png`, `4.png`. Порядок соответствует плоскостям:

| Изображение | Расстояние от ДОЭ |
|---|---:|
| `1.png` | 24,1 мм |
| `2.png` | 25,3 мм |
| `3.png` | 26,5 мм |
| `4.png` | 27,7 мм |

Для произвольных имён точный порядок можно задать явно:

```bash
docker run --rm --network none \
  -v "$PWD/input:/input:ro" \
  -v "$PWD/output:/output" \
  photonics-doe \
  --images /input/a.png /input/b.png /input/c.png /input/d.png \
  --output /output/phase.png
```

Входы должны иметь размер строго 128×128. Поддерживаются PNG, JPEG, BMP,
TIFF и WebP с одним кадром. Цветные изображения преобразуются в Grayscale,
значения пикселей делятся на 255. Изменение размера не выполняется.
При неверном количестве или размере изображений программа завершится с
ненулевым кодом и сообщением об ошибке. Все комплекты проверяются перед записью
первого результата. Существующие выходные файлы с теми же именами перезаписываются.

## Модель и веса

`HologramUNet` получает тензор `[1, 4, 128, 128]` и предсказывает фазы
четырёх плоскостей. Два раунда обратного и прямого распространения Френеля
объединяют их в одну фазовую маску `[1, 1, 128, 128]`.
Длина волны — 532 нм, шаг пикселя ДОЭ — 10 мкм. Оптические параметры
содержатся в `config.py` и проверяются на совпадение с checkpoint.

Функция потерь:
`0.7 × (1 − SSIM) + 0.3 × (1 − Pearson)`.
Для запуска без доводки добавьте `--refine-steps 0`.
Дополнительные настройки: `--refine-lr 0.1`, `--threads 2`.

Checkpoint `weights/h100.pt` включён непосредственно в Git и Docker-образ;
Git LFS и внешние загрузки весов не требуются. SHA-256 файла:

```text
6157eab300dafa91b856b7a48334cc75a31fc26c8963218435674bb635bd84c2
```

Фаза `φ ∈ [−π, π]` кодируется по формуле
`round(255 × (φ + π) / (2π))`. Значение 0 соответствует `−π`,
255 соответствует `π`; выход содержит только фазовую маску.

## Проверка решения

Тесты запускаются внутри Docker, включая инференс с поставляемыми весами
на всех восьми демонстрационных комплектах:

```bash
docker build --target test -t photonics-doe-test .
```

Проверяются размер 128×128, режим Grayscale, 8 бит и тип цвета `0`
в заголовке PNG, использование обученного checkpoint, порядок всех четырёх
входов, доводка фазы, оптические операции и обработка неверных входов.
Те же проверки запускаются в GitHub Actions при push и pull request.

При наличии локального Python 3.12 решение можно запустить без Docker:

```bash
python -m pip install -r requirements.txt
python -m src.infer --input-dir examples --output-dir output
```

Для локального запуска тестов установите `requirements-dev.txt`
и выполните `python -m pytest -q`. Этот способ не требуется для проверки в Docker.

## Состав репозитория

|---|---|
| `src/model.py` | Архитектура нейросети |
| `src/infer.py` | Загрузка весов и командная строка генерации ДОЭ |
| `src/physics.py`, `src/reconstruction.py` | Распространение Френеля и реконструкции |
| `src/refinement.py`, `src/losses.py` | Доводка предсказанной фазы |
| `src/io.py` | Чтение входов и экспорт 8-битной маски |
| `config.py` | Оптические параметры |
| `weights/h100.pt` | Обученные веса |
| `examples/` | 8 комплектов по 4 изображения и манифест с контрольными суммами |
| `tests/` | Проверки инференса, формата и используемых вычислений |
| `Dockerfile`, `.dockerignore` | Самодостаточная сборка и проверка контейнера |
| `requirements.txt`, `requirements-dev.txt` | Версии зависимостей запуска и тестов |
| `.github/workflows/docker.yml` | Автоматическая проверка Docker-запуска |
